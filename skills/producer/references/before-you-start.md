# Before you start (learned on the MMH videos)

- Tell the user the plan and a rough time. Ask only what you can't infer: script, format (default 1920x1080, 25 fps; Shorts 1080x1920), and whether the VO exists.
- Files: every video gets its own dated folder in the connected folder **Claude video work** (`YYYY-MM-DD <name> (<brand>)/01_source, 02_voice, 03_project, 04_renders` + README + DELIVERY_NOTES). Check `_Global library/` and its README before downloading anything, and add reusable downloads there. Downloads is only a transfer stop.
- Never invent Berribot facts, customers, metrics or quotes. Study numbers must come from a source you have read; cite it in the delivery notes.
- Replicating someone else's reel: their script and pictures are references. Keep it an internal test unless the user rewrites the script, and say so in the delivery notes.
- Replicating an MMH reel: read its shot log from the style-bible analysis first (`notes/NN_<reel id>.md`, e.g. `02_DaIoeJuhUOE.md` for the PayPal Mafia reel) and follow it shot by shot, with its music-section map from earshot. Rebuild their edit with real material; don't improvise a new one.
- Show a short test (the first 20–30 s) before a full render. Deliver the MP4 plus the editable raea project (or the Remotion project, when Atheeb approved the fallback), and say what was checked and what wasn't.
- **QA your own draft before showing it.** The user asks "can you spot your faults"; the checklist exists so they don't have to find them.
- **Taking feedback:**
  - **Fix the class, not the instance.** When the user points at one frame (a corner caption, an uneven gap, a repeated shot), find every other instance of that problem in the whole video and fix those too. Say which other ones were fixed.
  - **A note that comes with a screenshot is about that exact shot.** Ryan v2: the "pan from Ryan to the gin" note came with a screenshot of the turkey still. Fixing only the opening made the user ask again ("image again?"). If the idea fits elsewhere too, do it in both places.
  - **When a note names a reference video or effect, download the reference and step through the frames of that effect before building it.** Don't rebuild it from the verbal description: Mahindra v1 got white blocks, but the reference inverts masked regions of the frame.
  - **If the user likes an effect, run it through the whole video** (varied, on cuts and key words), not just once.
